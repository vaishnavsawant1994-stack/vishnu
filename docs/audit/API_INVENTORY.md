# API inventory

**Baseline SHA:** `a8d3310b4d9090a42800621b1b27cb6045443c1e`.

`api_inventory.json` is generated by parsing Python route decorators outside tests. The refreshed source-wide Python scan found 818 static route declarations.

Each static route record includes method, path assembled from statically declared router prefix, module, handler, and explicit `NOT VERIFIED` values for authentication, approval and runtime status. The parser does not resolve dynamic prefixes, mounts, dependencies, middleware, route inclusion order, authorization semantics, response schemas, or actual client consumers. It can therefore overcount unused declarations and undercount dynamic/non-Python endpoints. It is a route index, not a security audit.

## Router families found in source

- Core/local: `server/api.py`, `app/api.py`, `server/hosted_runtime.py`.
- PWA/owner: `server/cloud_app.py`, `server/iphone_pwa.py`, `server/owner_product.py`, owner memory/knowledge, preferences, backup, workflows, emergency stop, model/provider and release APIs.
- Capability/integration: connector/OAuth, capability console, capability forge/V3, OpenAPI/MCP and provider-specific routers.
- Device/perception: DeviceRegistry/device presence, physical/native Sensorium, context/world Sensorium V2/V3, camera, voice, wearable/IoT and device-lab qualification.
- Work/products: project/work-order/workforce, work attention, product composer, product distribution/runners, automation, evidence, release control.
- Supporting: identity, recovery, continuity, audit, notification, visualization, file/content ingestion and cloud/model runtime.

For authorization review, start from route handler then follow the injected auth dependency to the canonical owner/device authority and any ApprovalManager/ToolRegistry call. Do not rely on the path prefix or a UI's hidden state as authorization. Production endpoint exposure was not probed.
